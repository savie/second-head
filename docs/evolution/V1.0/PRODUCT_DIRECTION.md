# SECOND HEAD V1.0 — PRODUCT DIRECTION

Status: **WORKING / NON-CANONICAL**

## Core direction

The working product direction from brainstorming is:

> SECOND HEAD should not be treated as merely a chatbot or a conventional personal AI assistant.

The recurring mental model is:

- model / AI = **brain**;
- SH = **system, identity and continuity**;
- Hands / Tools = **ability to act**.

The product should therefore feel like a lightweight AI environment rather than a dashboard full of controls.

## UX direction

The intended experience is:

- modern;
- clean;
- conversation-first;
- lightweight on mobile;
- capable without exposing unnecessary system complexity.

The reference point discussed was the usability of modern ChatGPT-like interfaces, while retaining SH's own identity and architecture.

Possible high-level navigation:

```
Home / Chat
   ↓
drawer
   ├── Chats
   ├── Projects
   ├── Memory
   ├── Knowledge
   ├── Journey
   ├── Tools
   ├── Extensions
   └── Settings
```

This is a UX exploration, not a Canonical navigation requirement.

## Capability direction

The brainstorming identified a broad V1.0 capability set:

- conversational AI;
- Memory;
- Knowledge;
- Experience;
- Journey;
- multimodal input;
- image understanding;
- image generation;
- file intelligence;
- global search;
- Projects;
- Tools;
- Extensions / Plugins;
- lifecycle capabilities where already supported by the system.

The list is a planning inventory, not a guarantee that every item ships in the first release.

## Product principle

The key quality bar is:

> **Do not add a button merely because the capability exists on paper.**

A feature should feel real, usable, and connected to the underlying SH system.

The product should distinguish:

```
USER UX
  ↓
friendly / understandable
  ↓
technical diagnostic
  ↓
detailed when needed
```

rather than exposing raw runtime/provider errors to ordinary users.

## Relationship to Canonical

This direction intentionally leaves room for UX and product evolution without modifying Canonical.

Canonical defines system authority/semantics. Evolution defines how we may build a better product experience around that system.
