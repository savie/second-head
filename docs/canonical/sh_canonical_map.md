## Invariant Fundamental Saat Ini

- 1 Email = 1 Account = 1 Primary SH.
- DECOMMISSION ≠ Immediate Permanent Delete.
- USER_SH Clone = Owner Approval + Agreement.
- CLONE_SH ≠ SOURCE_SH.
- CREATOR_SH is NON-CLONABLE.
- INHERITANCE ≠ CLONE.
- INHERITANCE ≠ Identity Transfer.
- EVOLUTION ≠ Ownership Transfer.
- Evolution / Migration / Recovery ≠ New SH Identity.
- Core Evolution memerlukan Governance / Review.

## Canonical Addendum Saat Ini

Canonical Addendum saat ini menetapkan: Privacy / Visibility ≠ Transfer Eligibility. PRIVATE / OWNER-ONLY tidak boleh diinferensikan sebagai NON-TRANSFERABLE. Semantik transfer, inheritance, succession, dan legacy tetap tunduk pada explicit authorization dan aturan Canonical saat ini.

## SH Core

SH Core adalah foundational and governing core of SECOND HEAD yang menjaga identity, continuity, governance, privacy, dan system integrity lintas users, SH instances, models, runtimes, infrastructure, dan system evolution.

Lapisan yang saling terkait:

```
Fundamental / Governance
        ↓
Architectural / System
        ↓
Runtime / Operational
        ↓
Experiential
```

## Canonical Identity Boundaries

```
Model ≠ SH Identity;
Runtime ≠ SH Identity;
Database ≠ SH Identity;
Hardware ≠ SH Identity;
Account_ID ≠ SH_ID;
Session_ID ≠ SH_ID;
Memory ≠ SH Identity.
```

Account, SH identity, ownership, dan session tidak boleh dilebur hanya karena digunakan dalam satu application flow.

## Canonical Governance & Privacy

```
Creator Authority ≠ Private Data Access;
SH-000 Core Authority ≠ Private Data Access;
Runtime Access ≠ Ownership;
System Governance ≠ Omniscient Data Access;
Private Data Isolated by Default;
Shared Core ≠ Shared Private Memory;
Learning ≠ Automatic Core Modification.
```

Privacy dan authorization adalah boundary sistem, bukan sekadar perilaku UI.

## Canonical Continuity / Evolution

```
CLONE_SH ≠ SOURCE_SH;
CREATOR_SH is NON-CLONABLE;
INHERITANCE ≠ CLONE;
INHERITANCE ≠ Identity Transfer;
EVOLUTION ≠ Ownership Transfer;
Evolution / Migration / Recovery ≠ New SH Identity.
```

Perubahan model, runtime, infrastructure, storage, recovery, atau evolution tidak dengan sendirinya membuat SH baru.

## Canonical Boundary untuk Evolution

Evolution boleh mengembangkan architecture, UX, runtime, model abstraction, capability, dan system knowledge, tetapi tidak boleh diam-diam mengubah fundamental identity, governance, privacy, ownership, atau continuity semantics.
